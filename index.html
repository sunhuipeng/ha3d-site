认识插件

引擎只认三种插件 kind

kind 决定引擎把插件"挂"在哪、坐标系怎么算、生命周期怎么走—— 但「注册 → 声明造型 → 响应状态」这套骨架三种完全同构，会写一种，另外两种就是换个挂载点。

亮点 · 背景插件

背景板只画房子以外，但它是立体的

大多数 3D 户型工具的背景就是铺一张图。这里的 background 插件只负责 房子之外的那一层——地面、起伏地形、草叶、树、石头、围墙、远山与雾； 你的户型则是被"放"在这块立体面上。所以它的 apply() 统一返回一个 THREE.Group：没有「平面 / 立体」两种模式，扁平只是一块"比较扁的 3D 模型"。

房子坐落在它上面

ctx.house 给出全屋包围盒（宽 / 深 / 中心 / 楼层数）：地面托在房屋脚下，草和树沿占地一圈圈向外铺开，越远越稀。

只画外面，绝不越界

ctx.safe.allowed(x, z) 一次性排除房屋占地 + 1.5m 走廊；撒任何道具前问一句，草不会长到墙里、也不会冒在客厅地板上。

换户型，自动重排

house.hash 变化就重放背景，并按新占地重新避让；同一栋房子每次重建位置完全一致，因为它是随机种子的来源。

内置 🌿 草地🏖 沙滩🧱 石板🪵 木栈道 ❄️ 雪地💧 水面 动态 15Hz🌾 草原 真 3D 草丛

想要城市夜景、雪山林场、日式枯山水？复制一个 style 写进 custom/plugins/background/ 就生效——同 id 覆盖内置，升级镜像也不会丢。 

// 草原背景：底图平面 + 真 3D 草叶体块（同一 group 混搭）
g.add(ctx.plane(bgMeadowBase(1024)));
while (spots.length < o.clumps) {
  const x = h.cx + Math.cos(a) * rad;
  const z = h.cy + Math.sin(a) * rad;
  if (!ctx.safe.allowed(x, z)) continue;  // 避开房子
  spots.push({ x, z, w, h });

亮点 · 门窗插件

门和窗不是摆设，是墙上会动的洞口

门窗插件的锚点由引擎钉在门洞地面中心：你只管做样式，贴墙、朝向、随洞口等比缩放全部自动。 造型是 预绘制 GLB（框）+ 代码组装（扇）——门框窗框用 GLB 保住精致外观，铰链、玻璃、开合角度交给代码； 状态一来（门磁 on、开度 45%），转动的就是真实 GLB 部件。2D 户型图上的开门弧线同样不是贴图，是 plan2d() 现场画的。

钉在洞口上，永远不悬空

锚点 = 洞口地面中心，宽度随洞口等比缩放；挪墙、改墙厚、换楼层，门窗自动跟着走，摆位一次都不用重做。

同一个洞口，随意换样式

同 type 插件的样式自动聚合进编辑器同一下拉：单开门、双开门、卷帘门随时切，实体绑定原样保留。

状态驱动开合，还带缓动

isOn() 读门磁 / 窗磁，ctx.animate 每帧把铰链 Group 转向目标角——像真门一样有惯性，而不是瞬间跳变。

内置 🚪 单开门🚪 双开门🪟 推拉窗🪟 对开窗 🖼️ 固定窗🎚️ 卷帘门 custom

想要子母门、折叠门、百叶窗？把 frame / leaf 的 GLB 放进插件目录、改几行组装代码就生效—— custom/plugins/ 同 id 覆盖内置，升级镜像也不会丢。 

// 双开门：GLB 门框 + 两扇 GLB 门叶挂上铰链 Group
const leaf = await ctx.glb('models/leaf.glb');
const hinge = new ctx.THREE.Group();
hinge.position.set(right ? L / 2 : -L / 2, 0, 0);
if (right) leaf.rotation.y = Math.PI;   // 右扇镜像
hinge.add(leaf); g.add(hinge);
ctx.animate((dt) => { hinge.rotation.y += (target - hinge.rotation.y) * Math.min(1, dt * 4.5); });
亮点 · 设备插件

每台设备都是 HA 状态的 3D 化身

设备插件的 type 就是 HA 实体域（light / switch / cover / climate…），它决定能绑哪些实体，也定义「状态长什么样」。 浏览器里点一下台灯，真实世界的灯就亮了；HA 推回亮度 30%，3D 灯罩立刻微亮—— 控制（click → call_service）与呈现（update ← 状态推送）走的是同一条 WebSocket 长连接。

点击即控制，不用刷新

click 直连 HA 服务：大屏上点开关、拉窗帘、调空调，call_service 直接下发，回执点亮 ✓。

状态 → 形态的翻译器

model3d 返回 { group, update, dispose }，每次推送都进 update：呼吸灯、温度屏、扇叶转速、窗帘开合全是它画的。

fields 一处声明，面板自动生成

声明一次扩展字段，编辑器右侧属性面板自动长出表单；stateText() 决定大屏上设备头顶那行字——“76% 亮度 · 有人”。

模型绘制

模型从哪来 GLB × 代码

插件为什么一定要写代码？因为同一个造型在 开 / 关、开合角度、亮度、色温 下要变样子—— 这是插件的本职。所以分工很清楚：GLB 负责"静态长什么样"（精细外观交给建模工具）， 代码只负责"怎么拼、怎么变"（组合、尺寸、材质、动画）。三种组合方式，按造型复杂度挑一种或混用。

GLB 预绘制 代码绘制 / 控制
① 纯代码绘制 0 资源

用 ctx.box / cyl / sphere 现拼，十几行就是一件小设备。尺寸直接吃用户摆位时的参数，改色改高不用重导入。

// 扫地机：扁圆机身 + 雷达凸台 + 状态环
ctx.cyl(g, .17, .17, .08, 24, 0, .04, 0, '#2f353c');
ctx.cyl(g, .05, .05, .015, 16, 0, .088, 0, '#555c66');
扫地机 · 台灯 · 墙壁插座 · 门铃
② 单个 GLB + 代码 最常用

外观交给提前做好的 GLB，代码只干三件事：按洞口 / 墙面尺寸等比缩放、摆到锚点、把状态映射成开合或发光。

await ctx.frame(g, L, 0.9);           // 门框 GLB，按洞宽缩放
ctx.box(g, L - .1, 1.1, .03, 0, 1.5, 0, ...);  // 代码补玻璃
固定窗 · 平开门 · 24 种家具 · 摄像头
③ 多个 GLB 组合 + 代码 可动机构

把模型拆成几个可动部件分别预绘制，代码建 Group 当铰链轴、克隆、镜像、做缓动——静态零件就变成了机构。

const leaf = await ctx.glb('models/leaf.glb');
left.add(leaf.clone(true)); right.add(leaf.clone(true));
ctx.animate(dt => hinge.rotation.y += (t - hinge.rotation.y) * dt * 4.5);
双开门 · 推拉窗 · 窗帘（多片开合）
所以代码省不掉 GLB 能省掉"画"的功夫，省不掉"变"的逻辑：门磁 on → 门扇转到 90°、灯亮度 30% → 灯罩只微微亮、窗帘开一半 → 两片各退一半。这些都得由 update() + ctx.animate(dt) 实时算出来。 GLB 越精细，代码越少 → 但"状态 → 形态"永远在代码里
开始部署

两个项目，都在自己家里跑起来

都是单容器、一条 起来。Home 挂两个卷（户型 + 自定义插件），Studio 挂一个卷（插件项目），升级镜像都不丢数据。docker compose up -d --build

01 HA 3D Home 主应用 · 8099 · 128MB · data + custom 两个卷
1
起服务

docker compose up -d --build，或本地直接 node server.js（无需 npm install）。

2
打开 8099

浏览器访问 http://主机IP:8099，左上是编辑器，右上角「连接」配 HA。

3
填地址与令牌

HA 地址（如 http://主机IP:8123）+ 长期访问令牌，保存即连。

4
画你的家

先把墙画出来，家具设备随手摆，然后打开 display.html 挂到平板上。

⚠️ 令牌会下发到浏览器用于直连 HA WebSocket，请只在可信内网使用。

docker-compose.yml 
services:
  ha-3d-home:
    build: .
    image: ha-3d-home:latest
    container_name: ha-3d-home
    ports:
      - "8099:8099"
    volumes:
      - "$PWD/data:/data"       # 连接配置 + 户型项目
      - "$PWD/custom:/custom"   # 自定义模型与插件
    restart: unless-stopped
    mem_limit: 128m                 # 实际占用 50–60MB

没镜像仓库的机器（群晖 / 飞牛 / 内网机）用离线包：

# Apple Silicon 打 x86 镜像必须显式指定平台
npm run pack:image:amd64
# 产物 dist/ha-3d-home-1.0.0-amd64.tar → docker load
02 HA 3D Plugin Studio 插件工作台 · 8098 · 256MB · data 一个卷 · 内置 MCP Server
1
起服务

docker compose up -d --build，或本地 npm install && npm run client:build && npm start（首次需装依赖并构建前端）。

2
打开 8098

浏览器访问 http://主机IP:8098，新建插件项目：传 GLB、摆部件、绑 HA 实体，改动实时预览。

3
接入 AI

在 WorkBuddy 里添加 MCP 地址 http://主机IP:8098/mcp/sse， 26 个工具全流程可用，一句话让 AI 把插件写出来。

4
发布回 Home

Studio 设置里填 Home 地址（如 http://主机IP:8099）与安装密钥，一键发布——Home 需在线。

💡 两个容器在同一台机器上时，Studio 填 http://host.docker.internal:8099（Linux 用宿主机内网 IP）。

docker-compose.yml 
services:
  ha3d-plugin-studio:
    build: .
    image: ha3d-plugin-studio:latest
    container_name: ha3d-plugin-studio
    ports:
      - "8098:8098"
    volumes:
      - "./data:/data"          # 插件项目 + 全局配置
    environment:
      NODE_ENV: production
      PORT: 8098
      HA3D_STUDIO_DATA_DIR: /data     # 数据目录走卷
    restart: unless-stopped
    mem_limit: 256m                  # 拆 GLB / 打包时略吃内存

同样是离线包（镜像里已构建好前端与生产依赖）：

# 产物 dist/ha3d-plugin-studio-latest-<arch>.tar → docker load
npm run pack:image:amd64
📦 两个项目的 Docker 镜像暂时都未上传镜像仓库：可以先拉代码，在本地执行 docker compose up -d --build 或 npm run pack:image 打包后部署，步骤见上面两段。Studio 的部署说明也在 插件工作台 页面单独提供。
