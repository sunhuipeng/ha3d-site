8 天时间线

每天一次方向修正

按开发日志逐日还原。不是功能清单，而是「这天想明白了什么、推翻了什么」。

  1. Day 1 10-30

    从零到能用：一天跑完八轮

    架构奠基 自研开源版 8 轮迭代
    • 起点：参考项目只发闭源镜像，于是自研开源版，从一块地板开始搭。
    • 两个关键架构选择：前端直连 HA WebSocket（subscribe_entities 实时推送，绕开 CORS）；服务端零 npm 依赖（静态托管 + JSON 持久化 + REST 兜底代理）。
    • 同日八轮：Vue 3 重写 UI → 1s 防抖自动保存 → /display 大屏独立页 → 墙体真实掏洞（门留 2.05m、窗留 0.9~2.1m）→ 家具 GLB 资产化（自写生成器，20+ 模型）→ 设备造型表 → 背景插件化。
    • 当天就验证了「多背景插件并存」：background（地面）+ garden（院子）。
  2. Day 2 10-31

    把语义统一，替后面的插件体系铺路

    语义统一 插件契约
    • 2D 的「开 / 关」判定改为跟随插件自己的 click.isOn，不再由客户端猜设备类型。
    • 背景插件 API 统一成「返回一个 group」，和 3D 设备同构 —— 后面才能一视同仁地渲染。
    • 家具图标搬进 catalog.json；字段 dtype → type 统一。
    • 全量注释 / 文档审查一轮，准备对外发行。
  3. Day 3 11-01

    收敛与重构：技术债日

    重构 撤销 / 重做
    • 连续三轮「收敛」批次：消重复代码、属性面板统一。
    • 撤销 / 重做（快照式）落地；贴图逻辑整体重做。
    • 数据展示与大屏配置改为楼层级存储。
    • 脏数据防线：保存时前端自上而下重建整个 project，服务端只做校验。
    • 插件体系 backgrounds → styles：背景也变成一种「样式」。
  4. Day 4 11-02

    studio 诞生：从「改代码」到「点界面」

    新项目 部件体系 AI 面板
    • 前端拆成启动页 + 编辑页双页结构（hash 路由），Element Plus 整体改造。
    • 部件面板：模型库 / 大图预览 / 多节点子列表 / 部件锁定 / pivot·axis 旋转体系 + 方向 gizmo（最后收敛到世界坐标）。
    • AI 面板：需求描述 → 前端合成提示词、参考图上传（哈希命名 + 可改名）、18 张四视图卡片做上下文。
    • 多节点 GLB 支持，拆分两种模式（全拆 / 单拆）。
  5. Day 5 11-03

    MCP + 技能：把「人操作界面」换成「AI 操作接口」

    转折点 删除内置 AI 第一个技能
    • 删掉 studio 内置的 AI 接口（OpenAI 兼容那套）—— 判断：生成能力不该长在开发台里，应该由外部 Agent 通过 MCP 驱动。
    • MCP 骨架：SSE 传输 + WebSocket 中继（服务端 ↔ 浏览器编辑页），工具集重构为「以插件代码为中心」。
    • 第一个技能 ha3d-plugin-dev 诞生；用它写出第一批插件：门窗、落地灯。
    • studio 发布改为远程安装（主机地址 + 安装密钥），不再手动拷文件。
    • home 侧：插件导入 / 安装 + 服务端模块化 + 「自定义」角标。

    当天推翻：把「AI 面板」从产品里删掉，改成一个能被任意 Agent 调用的 MCP Server。

  6. Day 6 11-04

    双线并进，顺手把展示站也起了

    方案 B 2D 编辑体验 建站
    • studio：options schema 升级、左下卡片栈、valueType / enumValues、GLB 材质修复工具。
    • 方案 B 落地 —— styles / fields 一律以项目配置为准，代码里那份不再算数；配置快照漂移提醒 + 多标签页收敛；项目导入 / 导出。
    • home：户型尺寸按楼层、墙端点拖拽、2D 刻度尺 + 墙长标注、画墙 / 拖端点 Shift 正交。
    • ha3d-site 建站：studio.html 上线「提示词 → 生成 → 预览」区块与真实案例。
  7. Day 7 11-05

    架构收敛：只留一个判定入口

    废弃 opening isOn 顶层化 开源协议
    • studio：数据源全面切到引擎内存 + respawn 快速重生；配置全量覆盖落盘；「代码基线漂移」取代旧快照。
    • home：2D / 大屏的「已开启」判定链路收口；门窗并入 device（废弃 opening）。
    • 废弃 click.isOn，统一到顶层 isOn(obj, get) —— 判定只写一次，标签 / 2D 填充 / 点击方向都读它。
    • studio_sync_config + studio_render 上线；技能改名 ha3d-plugin-studio。
    • 两个项目加 PolyForm Noncommercial 1.0.0 协议。
  8. Day 8 11-06

    体验打磨与工程化收尾

    交互细节 配置锁 打包压缩
    • 交互：2D 状态条左移、「点击动作」下拉（10 组开 / 关服务全局拉平，不按设备类型分）、门窗特判清理（rot 统一为度、几何缺省声明化）、2D 居中按钮。
    • 插件 click 支持自定义函数 (obj, api)；顺手修掉 HA.callService 把参数全塞 target 的 bug。
    • studio 配置锁（人机互斥）：三版收敛，最终落到「每个控件 :disabled」。
    • 打包工程化：Docker 构建期压缩 js / css / html / json → 改为源目录只读、产物写 dist-min/。
    • 技能独立成仓库，按流程图重排流程：锁定 → 配置项同步 → 生成代码 → 验证 → 解锁。
决策对照

8 个被推翻的设计

这部分比功能列表更有意思：当时为什么那么做、后来为什么必须改。 有些是当天推翻，有些是三天后才发现撑不住。

01
当初

click 里藏 isOn 判定

↓
改成

插件顶层 isOn(obj, get) 唯一入口

为什么

判定散落在点击配置里，3D 标签 / 2D 填充 / 点击方向各算一遍，迟早不一致，且插件作者根本不知道该信哪个。

02
当初

插件分三类：设备 / 门窗（opening）/ 背景

↓
改成

两类：device（含门 / 窗，type 区分）+ background

为什么

门窗本质就是「贴墙的设备」，独立一类会带出一堆 type==='door' 特判；合并后点击、开关、绑定实体全部走同一套规则。

03
当初

styles / fields 以代码里注册的为准

↓
改成

以项目配置为准，代码里那份只是「自带初始值」

为什么

用户在面板改了配置、代码没跟着变，就会出现「配置改了画面没变」的经典坑 —— 这就是后来定的方案 B。

04
当初

写完代码再同步配置

↓
改成

先 sync_config 覆盖配置，再按新配置写代码

为什么

引擎渲染时配置会覆盖代码声明，顺序反了等于在错误的基线上验证，结论全都不可信。

05
当初

配置锁状态存在服务端，接口拦截 AI 写入

↓
改成

纯前端状态 → 最终每个控件 :disabled，刷新即解锁

为什么

服务端存锁会让刷新后「锁死解不开」；事件拦截又太重。锁只要防住「当前页面的人手改」，控件级禁用最直白。

06
当初

Docker 构建时原地压缩 public/、assets/

↓
改成

读源目录 → 写独立的 dist-min/，源文件一个字节不动

为什么

本地压过一次之后，源码就变成不可读的压缩产物，后面根本没法改（home 尤其致命）。

07
当初

studio 内置 AI 生成接口（OpenAI 兼容）

↓
改成

外部 Agent + MCP，开发台只提供可被调用的能力

为什么

生成能力属于 Agent，不属于开发台。拆开之后，模型随便换，工具集反而越做越实（现在 30 个）。

08
当初

技能包放在 studio/skill/ 里一起维护

↓
改成

独立仓库 ha3d-skill + 安装说明

为什么

技能的迭代节奏比 studio 快得多，混在一个仓库里必然版本分叉；拆开后还能单独 clone 装进任意 WorkBuddy。

架构演进

三个阶段，三次换挡

每一阶段解决的都是上一阶段暴露出来的问题：能看见 → 能造 → 能教 AI 自己造。

阶段一 · Day 1-3

单机可视化

浏览器直连 HA WebSocket，零依赖 Node 只做静态托管与持久化。核心是「2D 户型 → 3D 渲染 → 大屏展示」，设备与背景全部插件化。

2D 户型→3D 全屋→大屏控制
阶段二 · Day 4-6

开发台 + MCP

人点界面造插件：装配 GLB、绑实体、实时预览、导出/远程安装回 home。MCP Server 通过 SSE + WS 中继把浏览器编辑页变成 AI 可操作的接口。

studio 界面→MCP Server→AI 调用
阶段三 · Day 5 末-8

技能化全流程

一句话需求交给 WorkBuddy + 技能包：锁配置 → 拉配置与代码 → 配置项同步 → 生成代码 → 构造实体状态验证 → 解锁汇报。人只负责定方向与验收。

一句话需求→技能流程→插件包
